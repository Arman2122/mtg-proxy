# Secret rotation with an overlap period (piece R): same-session A/B on the box, 2026-10-12
#
# Binaries (GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go test -c ./mtglib/), run on 5.75.199.10 (2 vCPU Skylake, no SHA-NI, shared with a
# database; load 0.04-0.6 at the start, other tenants logged in), from /root/mtg-bench (deleted afterwards):
#   old = commit 8577930, the tree just before the first code change of piece R (piece B's code + the rotation spec)
#   new = commit 9d126e3 (the final CODE of piece R; every later commit is documentation or fixes found by the last review)
#   Both binaries also contain one extra benchmark file, compiled in by `go test -overlay` and NOT committed
#   (benchmarks BuildSecretSet/secrets=5000: the no-retiring build through buildSecretSet, a symbol present on both commits),
#   because buildSecretSetAt, which the new rows call, does not exist at 8577930.
# Protocol: alternating process runs, the order swapped every iteration, `-test.cpu 2 -test.benchtime 1s -test.benchmem`,
#   TIME_WAIT < 200 between runs, benchstat default settings (alpha 0.05):
#   1. existing handshake rows   '^BenchmarkDoorHandshake$/^(ee-unpaced|dd)$' (21 rows)  old vs new, 10 iterations
#   2. scan budget               '^BenchmarkScanBudgetReserve$'                           old vs new, 10 iterations
#   3. no-retiring set build     '^BenchmarkBuildSecretSet$' (the overlay twin)          old vs new, 10 iterations
#   4. NEW rows, new binary only '^(BenchmarkDoorHandshakeRetiring|BenchmarkBuildSecretSetAt|BenchmarkCloseStaleConns)$', 3 passes
#      (n = 3: benchstat gives no confidence interval, the figures are indicative)
#   5. informational: door bulk  '^BenchmarkDoorBulk$' (18 rows)                         old vs new, 5 iterations
# A first full run the same afternoon (without -test.benchmem, before the last row additions) agreed: every one of the 21 handshake
# rows `~`, geomean -0.35%; scan budget `~`; bulk `~` (geomean -0.22%). Its raw files are not kept here.
#
# RESULT (read before the tables)
#  * The bar (plan, Task 13): no significant regression above 3% at p < 0.05 on the existing rows, and allocs/op unchanged.
#    sec/op: no existing handshake row differs (all 21 rows `~`, p between 0.105 and 1.000); the geomean reads +1.20% in this run
#    and -0.35% in the first, i.e. it moves with session noise (individual rows carry +-4-14%). The two rows nearest the line:
#    dd/secrets=5000/last +5.0% (p = 0.105, noise +-12% on the new side) and dd/secrets=1/first +2.6% (p = 0.165).
#    allocs/op: equal on 20 of the 21 rows; the 21st, dd/secrets=5000/last, has one allocation fewer in about 15,170 (-0.00%, p = 0.033).
#  * B/op: +0.03% to +0.38% on 10 of the 21 rows (p < 0.05): about 50-60 bytes per connection (dd 15.70 KiB -> 15.75 KiB), the
#    attribution/stream-context fields the matched key travels in. Not a count of allocations (allocs/op is equal).
#  * Scan budget: keyed 411.7 ns -> 413.4 ns (p = 0.343), unkeyed 300.2 ns -> 305.7 ns (p = 0.280); 1 alloc, 96 B both.
#  * The no-retiring set build (5,000 ee secrets, the builder every swap/reload/PUT runs): 12.03 ms -> 11.79 ms (p = 0.579),
#    allocs/op equal (30.06k), B/op +0.00%.
#  * Door bulk (informational): all 18 rows `~`, geomean -0.91% in time.
#  * NEW rows (new binary, medians of 3; each `old` row is a client connecting on a RETIRING key; the `control` row is the
#    existing `last` row at N+R candidates in the same binary and session, with no retiring entries):
#      ee unhinted, secrets=5000: retiring=1 15.73 ms (control 15.93), retiring=100 16.11 ms (control 15.90)   -> within noise of the control
#      ee unhinted, secrets=1000: retiring=1 4.146 ms (control 4.318), retiring=100 4.493 ms (control 4.444)
#      ee unhinted, secrets=100:  retiring=1 1.268 ms (control 1.323), retiring=100 1.575 ms (control 1.650)
#      ee HINTED (old key): 0.96-0.98 ms at every N and R (the existing hinted rows read 0.93-0.96 ms): a returning client on a
#        retiring key costs two verifications, independent of how many secrets and retiring keys the door hosts
#      dd, secrets=5000: retiring=1 5.601 ms (control 5.510), retiring=100 5.689 ms (control 5.766)
#      BuildSecretSetAt, 5,000 secrets: retiring=0 12.12 ms, retiring=100 12.34 ms (+1.8%), retiring=4096 24.98 ms (2.1x, the cap)
#      CloseStaleConns, 10,000 streams: rotation (every stream judged by its own key) 2.50 ms with 0 allocs; unrelated swap
#        (the held-key fast path) 0.607 ms; unrelated swap with no retiring entries at all 0.513 ms; expiry (the swap that ENDS an
#        overlap: judges, collects and cancels 10,000 streams) 7.72 ms
#    So a client on a retiring key walks N+R candidates like any later primary, a hinted one never scans, and building/judging with
#    retiring entries costs what the number of entries says.
#  * Unix-only tests (cross-compiled, no -race) ran in the same session: internal/rotation 139 passes, internal/cli 342 passes as root
#    and 339 as an emulated non-root (user namespace, uid 1000, no capabilities: the box's /root is 0700, so a real unprivileged user
#    cannot run a binary from /root/mtg-bench); 0 failures; the skips are the root-only and non-root-only cases by design.
#    Six sabotaged builds (temp file 0644, no SIGPIPE handling, 32-bit uid cap, no chmod, no chown, no symlink resolution) each fail
#    their Unix-only test. The real linux binary was run end to end against a running proxy: rotate-secret --reload, the read-back,
#    --end-overlap, a closed stdout, an unreachable management API, and real SIGINT/SIGTERM/SIGHUP during a stalled --reload.
#
