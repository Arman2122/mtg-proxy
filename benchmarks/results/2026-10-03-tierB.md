# Tier B: the real mtg-proxy binary under load

- **Code:** perf-measure at a34c2cc, cross-compiled (linux/amd64, `CGO_ENABLED=0`).
- **Box:** Linux 6.8 VM, 2 vCPU Intel Xeon (Skylake), loopback only, another
  project's database running alongside.
- **Run:** `taskset -c 1 ./mtgbench -bin ./mtg-proxy -pin 0 -dir ... -out ...`, in two
  parts with TIME_WAIT under 200 between them. The binary (the proxy, and the
  WEB relay) is pinned to core 0, mtgbench to core 1.
  1. `-scenarios bulk,handshake,latency,idle,contention,limiter,slow-reader`:
     18 minutes, 3 of them idle while TIME_WAIT from the WEB handshake cell cleared.
  2. `-scenarios caps,accounting`: 7 minutes.
- **Raw samples:** `2026-10-03-tierB.json`, every run of every cell.

- Handshake times include the proxy's SOCKS5 round trip to mtgbench's data centre.

### accounting

Clean: one connection uploads 8 MiB and downloads 16 MiB; the proxy's /stats bytes_in and bytes_out, and for WEB the relay's bytes.up and bytes.down (less the client's 64-byte obfuscated2 frame), minus what the client moved. Every difference must be 0. Abrupt: the client asks for 64 MiB, reads 4 MiB and resets; the proxy may have counted bytes still in buffers, so counted ≥ received and counted ≤ what the data centre sent is the bound, and the gap is reported.
